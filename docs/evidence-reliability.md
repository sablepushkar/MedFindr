# Sources and evidence in MedFindr

MedFindr can show two different things: a flag generated by its own rules, and information returned by a public drug-label lookup. I want these to remain visibly separate so a reader can tell where each part came from.

A retrieved record can include the source name, URL, query, retrieval time and retrieval status. If the lookup fails, the app should show an error state rather than imply that the medicine or label does not exist.

## Reproduce the signal check

~~~bash
python scripts/evaluate_signals.py
python scripts/evaluate_signals.py --json-out reports/signal-evaluation.json
python -m unittest discover -s tests -v
~~~

The report stores the fixture's SHA-256 hash and the source revision when running in GitHub Actions. The hash helps identify the input file used for a run. It does not prove that the examples are complete or correct.

## Limits

- The test cases are small and manually labelled.
- Source metadata makes a result easier to inspect, but it is not a regulated audit trail.
- A successful lookup does not mean the result is right for a particular person or country.
- The app is not a diagnosis tool and should not be used to make medication decisions.
